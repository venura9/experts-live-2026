The gap

Everyone has an AI mandate. Some people have a DLP policy.

  • Banks and insurers. Source code is the control environment. It does not leave.
  • Government and defence. Egress is blocked at the subnet, not the policy doc.
  • Consulting. Their code, their environment, their contract.

The real choice is not small model versus frontier model.

It is small model versus nothing at all, because nothing else clears the review board this year.

Definition

An on-device inference runtime with an OpenAI-shaped door.

  • ONNX Runtime underneath, picking NPU, GPU or CPU for the machine it lands on
  • A curated catalog: Phi, Qwen, Mistral, DeepSeek, GPT OSS, Whisper for audio
  • Native SDKs for C#, JavaScript, Python and Rust, plus an optional local web server
  • No API key, no per-token cost, no Azure subscription, no inbound network

Making it real

What changes when this is not a laptop

  • Agent placement. One pool per security zone, on infrastructure that already holds the code
  • Model supply chain. Download at image build, pin the exact ID, no runtime downloads. The agent subnet can then block egress entirely
  • Determinism. Temperature zero, prompt versioned in the repo, findings schema-validated. Review behaviour is reproducible and auditable
  • Scope. A path filter, not the whole repo. Predictable runtime, predictable cost of attention
  • Human in the loop. The model opens threads. It never approves. Branch policy still requires people

If you go hosted

What a hosted agent gives you

ResourceMicrosoft-hosted
CPU2 cores, no GPU, no NPU
RAM7 GB, 6 GB usable on Linux
Disk14 GB, ~10 GB free
Job timeout60 min private, 360 min public
Lifetimefresh VM, discarded after the job
  • Cache the model. Fresh VM every run means it re-downloads unless you cache it. That is minutes off a 60-minute budget
  • Go small. Two cores. A sub-1B model, not a 4B one, until you have measured it

Everyone asks whether the model is good enough. Wrong question.

Ask what happens when it is wrong. Design for that answer and a 3.8 billion parameter model is enough.

The invariant

The model can stop trading.
The model can never start trading.

Not a policy in a document. A property of the code: no path exists from model output to an order.

Generalising

Nothing here is about crypto

  • Payments. A model reads incident feeds and puts a hold on batch settlement. It cannot release one
  • Platform. A model reads telemetry and freezes deployments. It cannot approve one
  • Operations. A model reads vendor status pages and pauses a nightly job. A human restarts it

Same shape every time: the model holds the brake, never the accelerator.

Where this does not fit

What I would not use it for

  • Serving many concurrent users. It is a device runtime, not vLLM or Triton
  • Anything needing frontier reasoning. Narrow tasks with schemas, not open-ended judgement
  • Unsupervised authority to act. Every demo here has a human or a hard gate downstream
  • Model choice beyond the curated catalog. That constraint is deliberate and it is still a constraint
Tokenomics

Not every token needs a frontier model

WhereInput / 1M tokensOutput / 1M tokens
Frontier API (Opus-class)$5.00$25.00
Mid-tier API (Sonnet-class)$3.00$15.00
Local SLM (Foundry Local)$0$0
  • The pattern. A frontier model plans. A local SLM executes the narrow, repetitive steps: classification, extraction, validation, formatting. 80% of agent steps, close to zero marginal cost
  • Both demos are this pattern. PR review is classification against a schema. Risk sentinel is classification against a threshold. Neither needs frontier reasoning, both need to run thousands of times
  • The escalation path. When the local model is uncertain or the task is novel, route to the cloud. Foundry Local and Azure AI Foundry share an API shape, so the routing code is an if-statement, not a rewrite
